# 日常业务场景

用户要的常常不是一个太空产品，而是“让外卖 App / 后台 / 商城有点太空科技感”。这时太空是**语言**，不是题材：界面里不出现火箭和星球也成立，用户的任务一步都不能变难。

示例见 [`examples/scenarios/`](../examples/scenarios/index.html)。

## 先翻译，再上色

把业务对象对应到“仪器”里的东西，找到一两处真正说得通的，只在那里用太空语言：

| 业务对象 | 对应成 | 用什么控件 | 示例 |
| --- | --- | --- | --- |
| 订单 / 物流 / 审批进度 | 任务阶段、检查点 | `.o-track`、`.o-objectives` | 外卖、快递、报销审批 |
| 地图上的路线、移动的人或车 | 轨道与卫星 | SVG 路线 + 引线标注牌 | 外卖骑手、网约车、物流车队 |
| 剩余时间 | 倒计时 | `.o-arc` 刻度环 | 送达、取件、会议开始、抢购开场 |
| 余额、营业额、距离这类唯一的主数字 | 主读数 | 等宽 / tabular 大数字 | 钱包、看板、运动记录 |
| 预算、电量、存储、进度 | 刻度 | `.o-gauge`、`.o-arc` | 记账、设备、网盘 |
| 房间、门店、项目、账户 | 舱段 / 舰队 | `.o-list` 反白选中 | 智能家居、连锁门店、多账户 |
| 设备 / 服务状态 | 状态灯 | `.o-status`（形状 + 颜色 + 文字） | IoT、运维、门店告警 |
| 商品参数、卖点 | 工程图纸标注 | 引线 + 尺寸线 | 3C 电商、家具、汽车配置 |
| 明细数据 | 遥测表 | `.o-table`（数字右对齐） | 账单、分段成绩、门店明细 |

对不上的地方不要硬套：评论区、客服对话、长文章就用正常的排版，不要加网格和角标。

## 剂量

| 剂量 | 用在哪 | 做法 |
| --- | --- | --- |
| 轻 | 消费 App 的大部分页面（钱包、商城、内容） | 只换控件语法和数字字体，加一处主视觉（刻度环 / 标注图）；正常圆角可以保留 |
| 中 | 订单追踪、运动记录、智能家居 | 加上状态灯、步骤轨迹、引线标注；一种装饰语言（网格或星点） |
| 重 | 运营看板、监控大屏、品牌活动页 | 整页控制台布局、密集读数、状态排序；装饰语言仍然最多两种 |

## 不能变的东西

- **主任务一次可达。** “联系骑手”“立即购买”“转账”放在首屏，主按钮仍然是主按钮。按键提示 `[E]` 只给桌面键盘，手机上隐藏。
- **金额和时间按本地习惯写。** “¥ 49.50”“18:42 送达”“昨天 21:15”，不改成 “T−00:12:00” 或 UTC——那是给发射页的，日常业务会让人看不懂。
- **可读性优先于氛围。** 深色界面的正文对比度至少 4.5:1；长列表、表格的行高照常。
- **浅色也成立。** 用户的品牌是浅色时，用 `blueprint` 的线条语言配浅底，或只借控件语法，不必把产品改成黑底。
- **标注和对象共用一套坐标。** 地图、图纸上的标注牌和 SVG 放进同一个固定比例的容器里，不要让 SVG 用 `slice` 裁切、标注牌用百分比，二者会错位。

## 每个方向适合什么业务

| 方向 | 适合 | 不适合 |
| --- | --- | --- |
| 任务控制台 mission | 看板、运动数据、监控、交易终端 | 面向大众的轻量 App 首页 |
| 轨道蓝图 blueprint | 3C / 家居 / 汽车商品页、产品说明、SaaS 官网功能介绍 | 高频操作的工具界面 |
| 深空 deepfield | 金融账户、会员中心、品牌首页、音乐 / 冥想 | 信息密集的表格 |
| 星际拓荒 frontier | 订单追踪、智能家居、出行、游戏化的任务和成就 | 严肃的医疗、政务表单 |
