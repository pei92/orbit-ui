## 仪器的诚实

太空科技界面像一台仪器：每个元素都在测量、显示或操控一个东西。加任何装饰前问一句：它在测量什么？

- 网格要么对应真实坐标（经纬度、时间轴），要么只铺在一个“测量区”里，不作为全站壁纸。
- 定位角标（四角括号）表示“这块区域被锁定 / 被选中”，一屏最多一处。
- 标注线从被标注的物体出发，终点是文字；不画没有起点的装饰线。
- 刻度、单位、精度和真实场景一致：轨道高度到 0.1 km，速度到 m/s，时间用 UTC。

## 字体与数字

| 角色 | 建议 | 规则 |
| --- | --- | --- |
| 展示 | Space Grotesk、Sora、Saira、Michroma（仅短标题） | 只用于标题和极短编号；不全页使用 Orbitron 这类“科幻字”，它是模板标志 |
| 正文 | Inter、IBM Plex Sans，中文 HarmonyOS Sans / 思源黑体 | 14–16px，行高 1.6 以上 |
| 数据 | JetBrains Mono、IBM Plex Mono、Space Mono | `font-variant-numeric: tabular-nums`，刷新时宽度不变 |

- 等宽字是太空界面最强的识别特征，但它承担的是**数据**，不是所有文字。长段落用比例字体。
- 中文界面不要为了“科技”把标签写成英文全大写（“TELEMETRY”“STATUS”）。真实产品面向中文用户就写“遥测”“状态”；只有单位和型号（km/s、UTC、NORAD）保留原文。
- 超大数字（倒计时、主读数）按字形好看选字，单位用小一号、低对比的字跟在后面。

## 色彩与发光

- 底色带一点色相，不用纯 #000 铺大面积文字区域。
- 层级靠底色微差（surface / surface-2）和线的强弱，不靠阴影。深色界面里阴影几乎看不见，靠阴影分层是浅色思维的残留。
- 发光只给两类东西：正在发生的信号（直播、上行中、告警），以及全页唯一的主动作。
- 渐变只用来模拟真实的光：大气层边缘、恒星辉光、引擎尾焰。不给按钮和文字做彩虹渐变。
- 色板见 [`assets/orbit.css`](../assets/orbit.css) 的三套 `data-orbit`。

## 面板与线

- 面板用切角或直角 + 1px 细线；圆角不超过 4px。大圆角 + 毛玻璃是消费级 App 的语言，和仪器感冲突，除非方向就是“舱内材质”。
- 线的粗细对应层级：分版面用强线，分栏用弱线，全页一致。同一处不叠双线。
- 不把卡片套在卡片里。遥测面板里的分组靠标签和留白，不靠再画一个框。

## 控件语法

按钮、输入、开关、标签、状态灯用同一套逻辑：

- 形状：右上切角（`clip-path`），或纯直角。
- 标签：等宽、小号、低对比。
- 按下：下沉 1px，不缩放。
- 聚焦：2px 强调色描边，偏移 3px，键盘可见。
- 处理中：底部一条扫描进度，按钮宽度不变。
- 危险动作（中止、删除、断开链路）：告警色描边 + 二次确认，确认写清后果（“中止后本次发射窗口关闭，下次窗口 10 月 18 日 02:14 UTC”）。

## 线条语言

线是太空界面的骨架。每种线只做一件事，全页统一：

| 线 | 写法 | 用途 |
| --- | --- | --- |
| 分区线 | `.o-rule`：起点小实心圆，终点短竖刻度 | 区块之间的停顿；比普通 `<hr>` 多说一句“从这里开始、到这里结束” |
| 引线 | SVG：对象上一个实心底的圆 → 线从圆心出发 → 折一次 → 标注牌（圆画在线之后，盖住线头，任何尺寸都对齐） | 标注星球、轨道点、部件；只折一次，折角（45°、60° 或 90°）全页只用一种；引线不要和它标注的曲线同向离开锚点，否则两条线会粘在一起 |
| 刻度环 | `.o-arc`：外圈每 6° 一格短刻度，内圈细弧显示进度 | 倒计时、扫描进度、燃料；圆心放读数 |
| 涂装条 | `.o-stripe`：四色等宽色带 | 品牌位和一处主视觉；不当分隔线到处用 |
| 框 | 1px 弱线 + 3px 圆角，或切角 | 面板；同一页只用一种角 |

- 线宽只用 1px 和 1.5px 两种；1.5px 只给被选中或正在测量的对象。
- 端点装饰（圆点、刻度）是语言的一部分，但一条线最多两种端点。
- 引线和文字之间留 6–8px，不让线撞到字。
- 星际拓荒方向的选中态是**整行反白**，不是彩色描边；在 `.o-list` 里用 `aria-current="true"` 或 `aria-selected="true"`。

## 数据可视化

- 遥测曲线用细线 + 当前值点，网格只画主刻度。
- 轨道和星图用 SVG 自己画：椭圆、虚线未来轨迹、实线已飞轨迹、当前位置标记。
- 地球与行星：要真实就用 NASA Blue Marble 等公共素材或 three.js 地球，不手画写实行星。
- 雷达 / 极坐标图用于方位类数据，不为了“像科幻”把柱状数据画成雷达。

## 图标

- 工业仪器感：Carbon、Material Symbols Sharp、Tabler（1.5px），直角端点。
- 一个产品只用一套。能用字符就用字符：→ ↑ ▲ ● ◆ ⏵、编号。
- 不用表情符号（🚀🛰️）当界面图标。

## 可读性是交付门槛

- 深色底上正文对比度至少 4.5:1；`--o-text-dim` 只用于辅助信息，不用于正文。
- 正文不小于 14px，数据标签不小于 12px。不靠 10px 的小字营造“精密”。
- 发光文字（text-shadow）只用于大字号；小字加发光会糊。
- 在 1x 屏幕上检查 1px 细线和 0.1 透明度的网格是否还看得见。

## 太空界面的默认做法清单

以下是模型做“科技感”时最常见的默认，交付前逐条检查：要么删掉，要么在交付说明里写出它怎样服务方向。

- 全屏粒子 / 星空背景 + 居中大标题 + 两个按钮
- Orbitron 全站使用
- 霓虹青 #00ffff 发光描边到处都是
- 每张卡片都是毛玻璃 + 发光边
- 中文界面里满屏英文大写标签
- 渐变文字标题
- 装饰性雷达扫描、旋转圆环，与内容无关
- 假数据：“99.9% 可靠性”“1000+ 卫星”
- 表情符号火箭
